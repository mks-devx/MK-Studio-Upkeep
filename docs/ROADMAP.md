# Roadmap

The current focus is a reliable local inventory and clear routes to official developer support.

Release-specific evidence and remaining platform checks are recorded in
[Release verification](RELEASE_VERIFICATION.md).

Before the next maintenance release:

- Keep intact backups visible and restorable when another backup record is damaged.
- Handle damaged backup sizes without overflowing storage totals.
- Refresh software-manager discovery when the user requests a refresh.

Further work:

- Broaden reviewed website and manager recognition using synthetic identity fixtures and official sources.
- Improve local evidence and diagnostics for incomplete metadata and scan access limitations.
- Extend accessibility, clean-account, physical Intel and macOS-version validation.
- Keep limited removal conservative, recoverable and separate from read-only scanning.
- Validate additional vendor layouts with synthetic fixtures before extending removal eligibility.
- Resolve outstanding publication and rights obligations separately from technical release checks.

Automatic plugin release detection is outside the current product scope. Any future network service needs explicit consent, reliable source rights and measured coverage before it changes the interface. Windows and monitoring are future decisions rather than release commitments.
