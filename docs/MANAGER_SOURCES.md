# Software-manager reference sources

Reviewed 8 September 2026. The directory uses factual app names and official
navigation links, checked against the developer pages below. No page text,
installer, logo, release list or third-party application identifier is copied.
The retired package-index bundle-ID table has been replaced, including copies
in hardware and vendor routing. No reference page is fetched by the app.

Product bundle prefixes remain local routing heuristics based on vendor namespaces;
they are not assertions that a manager owns every product or that the publisher
of an installed app is verified. Name matches undergo signature verification
and explicit publisher confirmation before opening. Renamed/unregistered apps
may need to be opened manually. No guaranteed detection across all installations
is claimed. Official references establish names and routes, not installation paths.

## Verification and delivery boundary

The directory is included in v0.2.0. See [release verification](RELEASE_VERIFICATION.md)
for the released app's tests, packaging, signing and runtime checks.

The lookup uses documented names, the local application registry and standard
Applications folders. The name-based registry API is deprecated but remains
available on the minimum deployment target; the build reports that warning.
A read-only comparison of the previous and replacement lookup methods found no
previously discoverable manager missing after the filename-alias correction.
This is a bounded regression check, not verification of every supported manager
on every installation. Interactive checks were interrupted by changing app state.
No claim of recognition for every renamed app or installation layout is made.
Signature verification and publisher confirmation remain required before opening.

Historical source versions retain their original notices. Verification of the
released app does not establish recognition of every supported manager or legal
clearance for every source.
